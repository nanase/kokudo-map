# 国道マップ

日本の一般国道に特化した Web マップである。既存の地図では読み取れない二点を正面から扱う。

- 縮尺で番号が省略されない
  - 短い路線も、ズームを引いても番号が出る
- 重用区間で番号を丸めない
  - 同一区間に複数の国道が指定されているとき、番号の若いものだけでなく全指定を出す

地図に都道府県の選択はない。生成済みの地域をすべて 1 枚に重ねて出す。現在の範囲は長野県と新潟県である。範囲を広げるのは地域を足して生成する作業であって、画面の変更ではない。

## 動かす

```sh
mise trust                # 初回のみ
mise run build niigata    # 取得 → 判定 → 検証 → 式検証
mise run serve            # http://localhost:8000/
```

`?region=niigata` を付けると、その地域の位置で開く。出るデータは変わらない。初期表示の指定だけである。

| タスク | 内容 |
| --- | --- |
| `mise run build` | 取得から検証まで通す |
| `mise run rebuild` | キャッシュから作り直す。取得しない |
| `mise run audit` | 鎖が切れている路線を機械的に探す |
| `mise run serve` | ローカルサーバを起動する |
| `mise run render-check` | Chromium で実描画を確認する。`serve` を先に起動する |

`uv` が依存を解決するので pip install は不要である。Node は検証にのみ使う。パッケージ管理には bun を使う。

```sh
bun install
bun x playwright install chromium   # 実描画チェックにのみ必要
```

`bunfig.toml` で `minimumReleaseAge` を設定してあり、公開から 3 日経っていないパッケージは入らない。サプライチェーン攻撃で悪意あるバージョンが公開直後に出回っても、既知の期間はそれを踏まない。

```sh
bun run lint       # 静的検査
bun run format     # 整形
bun run lint:fix   # 安全な自動修正込みで検査
```

## 構成

| 場所 | 中身 |
| --- | --- |
| `web/` | 地図本体。MapLibre GL JS と生成済みデータ |
| `web/mapspec.mjs` | スタイルと絞り込み式の定義。検証スクリプトも同じ物を読む |
| `.claude/skills/national-route-data/` | 生成と品質管理の手順、判定ルール、スクリプト |
| `build/cache/` | Overpass の応答。再取得できるので成果物ではない |

判定ルール、不具合の切り分け、過去の判断は
[national-route-data スキル](.claude/skills/national-route-data/SKILL.md)
にまとめてある。

## データモデル

各区間に、そこを通る国道番号の集合を持たせる。これだけである。

```json
{
  "refs": ",18,117,406,",
  "refs_list": [18, 117, 406],
  "n": 3,
  "kind": "road",
  "src": "relation",
  "former": 0,
  "name": "国道18号",
  "updated": "2025-12-28",
  "km": 1.204
}
```

`refs` を区切り文字で囲むと、番号の照合が文字列包含で書ける。`,4,` は `,14,` や `,400,` に誤マッチしない。結果として UI の主要機能がすべて MapLibre の式に落ちる。

```js
["in", ",18,", ["get", "refs"]]   // 国道18号のみ
[">=", ["get", "n"], 2]           // 重用区間のみ
```

重用かどうかは道路の性質であって、選択の結果ではない。18 号と 117 号が重なる区間は、両方を選んでいなくても重用区間である。よって `n` だけで決まり、サーバ側の再計算はない。

地域ごとに生成した GeoJSON は、閲覧側で 1 つに繋ぐ。bbox は矩形なので継ぎ目で同じ道が二度届くが、OSM の way id が同一性そのものなので幾何の照合はいらない。

### アーク分割は不要だった

当初は指定路線の集合が変わる地点で線を分割する処理を想定していた。実データを見ると OSM の way はすでにその粒度で切れている。`ref` タグもリレーション所属も way 単位の属性なので、一本の way が指定の変化を跨ぐことは構造上ありえない。よって way がそのままアークになる。

## 結果

| 項目 | 長野県 | 新潟県 |
| --- | --- | --- |
| アーク | 7,872 | 8,412 |
| 実延長 | 3,447 km | 4,061 km |
| 指定延長。重用を重複計上 | 3,911 km | 5,020 km |
| 路線数 | 46 | 40 |
| 重用アーク | 1,028 | 1,999 |
| 最も深い重用 | 三重 | 六重 |
| 点線国道 | 11 と階段 1 | 33 |
| 工事中・事業中 | 74 | 70 |
| 海上国道 | 0 | 2 |
| 旧道 | 9 | 61 |
| 単一の鎖になった路線 | 27 / 46 | 28 / 40 |
| GeoJSON。gzip 前 | 4.25 MB | 4.72 MB |

路線数には bbox の食み出しで入った隣県の路線を含む。

閲覧側は両者を繋いで出す。重複する 1,097 アークを落として 15,187 アーク、6,974 km、75 路線になる。

新潟県は重用が濃い。新潟市の栗ノ木バイパスは 7・8・17・49・403・459 号の六重用で、約 4.2 km 続く。萬代橋の近くでは 7 路線が起終点を共有する。国道 350 号は佐渡を経由する海上国道なので、四つに分断されているのが正しい姿である。

長野県で最も深い重用は三重の 18・117・406 号で、長野市内の約 3.9 km である。国道 152 号は徒歩道 4 アークの地蔵峠と工事中 3 アークの青崩峠を持つ。

## 検証

| スクリプト | 何を見るか |
| --- | --- |
| `verify.py` | 生成データの整合性と既知の事実。長野 52 項目、新潟 47 項目 |
| `check_expressions.mjs` | 式とスタイルが MapLibre 仕様に適合するか。22 項目 |
| `render_check.mjs` | Chromium で実際に描画されるか。全地域が同時に出るかも確認する。画面写真は一時ディレクトリに残す |
| `audit.py` | どの路線が怪しいかを機械的に順位付けする |

地域ごとの既知の事実は `expectations.py` に分けてある。地域を足すのはデータの編集であって、コードの変更ではない。

`check_expressions.mjs` は `web/mapspec.mjs` を読み込んで検査する。式を書き写した初版は、複製が通るのに本物が MapLibre に拒否される状態を招いた。検証対象を書き写した時点で、検証は検証でなくなる。

## 既知の制約

- bbox で切っているため隣県が食み込む
  - 行政界でのクリップは未実装
  - 新潟県の bbox は南東の角で栃木県と福島県に及ぶ
- 起終点は暫定である
  - bbox の縁で切れた端点は除外している
  - 政令の別表との突き合わせは未実施
- glyphs は国土地理院のデモ配信を参照している
  - 本番では自前でホストする
- 海上国道は部分的である
  - リレーションに含まれる航路だけが入る
  - 新潟県の 350 号で 2 アーク
  - 車道と紛れないよう破線で描き、表示は個別に切り替えられる

  - 新潟市の栗ノ木バイパスが 7・8・17・49・403・459 号の六重用
- [ ] 起終点ラベルが長すぎる
  - 萬代橋の近くは 7 路線が起終点を共有し、`7・8・17・113・116・289・402` と伸びる
- [ ] 三重用の赤が広い面積を占め、単独指定が読み取りにくい

データ側に残っている作業は次のとおりである。

- [ ] 全国化

  - 全国分の GeoJSON は 70 MB 前後になる。1 ファイルで配るのは無理があり、ベクタタイル化も要る
