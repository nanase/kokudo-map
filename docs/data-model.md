# データモデル

[開発](development.md) から辿る詳細文書です。

各区間に、そこを通る国道番号の集合を持たせます。これだけです。

```json
{
  "refs": ",18,117,406,",
  "n": 3,
  "kind": "road",
  "src": "relation",
  "former": 0,
  "label": "18・117・406",
  "name": "国道18号",
  "updated": "2025-12-28",
  "km": 1.204
}
```

`refs` を区切り文字で囲むと、番号の照合が文字列包含で書けます。`,4,` は `,14,` や `,400,` に誤マッチしません。結果として UI の主要機能がすべて MapLibre の式に落ちます。

```js
["in", ",18,", ["get", "refs"]]   // 国道18号のみ
[">=", ["get", "n"], 2]           // 重用区間のみ
```

重用かどうかは道路の性質であって、選択の結果ではありません。18 号と 117 号が重なる区間は、両方を選んでいなくても重用区間です。よって `n` だけで決まり、サーバ側の再計算はありません。

## 台帳の起点・終点

区間の属性とは別に、路線そのものが持つ欄があります。一般国道の路線を指定する政令(昭和 40 年政令第 58 号)の別表から取り込んだ、459 路線ぶんの起点・終点・重要な経過地です。

```json
{
  "ref": 152,
  "start": { "name": "上田市", "lat": 36.37202, "lon": 138.293123, "how": "sole" },
  "end": { "name": "浜松市", "lat": 34.727896, "lon": 137.786078, "how": "junction" },
  "via": "長野県小県郡丸子町　同郡長門町　茅野市　…"
}
```

政令が書くのは地名だけです。座標は当てた物で、当て方は一つしかありません。

- その路線の端点のうち、政令の地名の市区町村に入るものを選ぶ

座標を作ることはありません。必ず路線が実際に途切れる節点であり、必ずその市区町村の中にあります。当たらなかった起終点は地名だけを持ち、`how` が理由を述べます。

| `how` | 意味 |
| --- | --- |
| `sole` | 市区町村内の端点が一つだけだった |
| `junction` | 複数のうち、最も多くの国道が集まる端点を選んだ |
| `farthest` | 複数のうち、路線の中心から最も遠い端点を選んだ |
| `no-boundary` | 市区町村の輪郭を特定できなかった。港湾・空港のほか、現行版にも 2000 年版にも無い地名が該当する |
| `no-endpoint` | 市区町村は特定できたが、その中に端点が無い |
| `ring` | 起点と終点が同じ市区町村にある環状路線。遠い側を採る規則が両端を区別できない |

地図が描く端点(`termini`)は変えていません。台帳の起終点は別の欄です。

## 路線どうしの関わり

区間の属性でも路線の欄でもなく、路線と路線のあいだにあるものです。詳細の箱が、いま見ている路線に関わる路線を並べるのに読みます。

| 関わり | 読む欄 | 意味 |
| --- | --- | --- |
| 重用 | `combinations` | 同じ道を一緒に走っている |
| 起終点の共有 | `shared_termini` | 路線の端が同じ地点にある |
| 交差 | `crossings` | 別々の道が平面で交わる |

前の二つは、すでにある欄がそのまま答えます。新しいのは `crossings` だけで、番号の組を並べただけの表です。

```json
"crossings": [[1, 246], [1, 247], [2, 9]]
```

交差点はアークの端とはかぎりません。OSM の way は交差のたびに切れているとはかぎらず、一方の途中の節点をもう一方の端が踏むことがあります。端だけを見ると、出会う組の 2% を取り落とします。よって節点を全部見ます。

立体交差はこの表に出ません。節点を共有しないためです。曲がれない交差は交差ではありません。

重用したことのある組も出しません。重用は `combinations` が述べているので、同じことを二箇所で言わないためです。同じ理由で、箱も強い関わりの節にだけ番号を出します。重用する相手は重用の切れ目で必ず交差もしますが、それを言い足しても読む人が知ることは増えません。

## アーク分割は不要だった

当初は指定路線の集合が変わる地点で線を分割する処理を想定していました。実データを見ると、OSM の way はすでにその粒度で切れています。`ref` タグもリレーション所属も way 単位の属性なので、一本の way が指定の変化を跨ぐことは構造上ありえません。よって way がそのままアークになります。
