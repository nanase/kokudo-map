# 検証

[開発](development.md) から辿る詳細文書です。

| スクリプト | 何を見るか |
| --- | --- |
| `verify.py` | 地域ごとの整合性と既知の事実 |
| `verify_national.py` | 結合後にしか答えられないこと。番号の漏れ、集計の突合、配信物、台帳の起終点 |
| `check_expressions.mjs` | 式とスタイルが MapLibre 仕様に適合するか |
| `render_check.mjs` | Chromium で実際に描画されるか。47 県ぶん確かめる |
| `compare_sources.py` | Overpass 由来の基準と pbf 由来の生成物を突き合わせる |
| `audit.py` | どの路線が怪しいかを機械的に順位付けする |
| `test/*.test.mjs` | 集計・絞り込み式・標識の作図。データが要らない |

地域ごとの既知の事実は `expectations.py` に分けてあります。地域を足すのはデータの編集であって、コードの変更ではありません。

`check_expressions.mjs` は `web/mapspec.mjs` を読み込んで検査します。式を書き写した初版は、複製が通るのに本物が MapLibre に拒否される状態を招きました。検証対象を書き写した時点で、検証は検証でなくなります。

この検査は二つに分かれます。仕様への適合はコードだけで答えられる問いなので、`--spec-only` を付ければデータの無い場所でも走ります。式を実データで評価する側は、生成済みの地域が要ります。

push と pull request では GitHub Actions が前者を回します。静的検査、単体テスト、仕様の検査、Python の構文、資材が組めること、共有用の札の差し替え先が残っていることを見ます。判定の正しさと実描画は 2.5 GB の pbf と 47 地域ぶんの生成を要求するので、手元でしか答えられません。`main` への配信は検査を通らなければ走りません。

単体テストが守るのは、この地図の存在理由そのものです。組み合わせ表を路線ごとに開く読み方(`routesOf`)と、選択が触れる行を一度ずつ足す読み方(`statsFor`)を取り違えると、重用区間を路線の数だけ数えてしまいます。それは地図が隠すのをやめさせたい数そのものです。実際に取り違えを作り込んで、テストが落ちることを確かめてあります。

番号がどの県に出たかは、県ごとの検査では言えません。裏取りは県の中で閉じているので、遠くの県への漏れはどの 1 県からも見えません。`verify_national.py` は路線ごとの実在範囲を見て、それを断定します。
