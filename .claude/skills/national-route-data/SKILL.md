# national-route-data — 国道データの生成と品質管理

OpenStreetMap から日本の一般国道を取り出し、重用区間の全指定を保ったまま `web/data/` の配信データに変換する。あわせて、地理院地図との相違を機械的に検出する。

対象は全国 47 都道府県である。

## 生成する

```sh
uv run scripts/extract_pbf.py     # pbf から 47 地域ぶんを切り出す
uv run scripts/build_all.py       # 判定・検証・結合・タイル化まで通す
```

初回は pbf が要る。約 2.5 GB である。

```sh
mise run fetch-pbf
```

段階は次のとおりである。

| 段階 | すること | 単位 |
| --- | --- | --- |
| 取得 | Geofabrik の pbf を落とす | 全国 |
| 切り出し | 地域ごとの生 OSM をキャッシュする | 全国を 1 度読む |
| 判定 | 国道かどうかと何号かを決める | 地域 |
| 検証 | 生成物の整合性と既知の事実を確認する | 地域 |
| 式検証 | 地図スタイルと絞り込み式を確認する | 地域 |
| 結合 | 地域を繋ぎ、集計してタイルを切る | 全国 |
| 全国検証 | 結合後にしか答えられないことを確認する | 全国 |

1 地域だけ Overpass から作り直すなら `uv run scripts/pipeline.py <地域>` を使う。全国を Overpass から取ってはいけない。47 都道府県は約 140 クエリ、raw 1 GB になり、公開ミラーの用途から外れる。

ブラウザでの実描画確認は `scripts/render_check.mjs` が担う。ローカルサーバを先に起動しておく必要がある。PMTiles は Range 要求で読むので、サーバは `scripts/serve.py` である。`python -m http.server` では配れない。

画面写真は一時ディレクトリに書き出し、最後にその場所を表示する。作業ツリーには残さない。手元に置きたいときだけ、保存先のディレクトリを引数で渡す。

## 判定は地域ごとに閉じている

取得は全国だが、裏取りは地域の中で閉じたままにする。ここを崩すと過去の不具合がまとめて戻る。

way 自身が主張する番号は、同じ地域の国道リレーションが独立に保証している番号だけ採る。この絞り込みが効くのは、保証集合が地域ぶんしかないからである。

| 範囲 | 保証された番号 |
| --- | --- |
| 1 県 | 数十 |
| 一般国道の全番号 | 459 |

全国をひとまとめに判定すると保証集合は 459 に近づき、何も濾さなくなる。国道 372 号は京都・兵庫に実在するので、長野県道 372 号がそのまま国道 372 号として復活する。過去の実例は [CASES.md](CASES.md) の 1 番と 2 番である。

`verify.py` は各地域の保証集合が 459 の三分の一未満であることを確かめる。`verify_national.py` は路線ごとの実在範囲を見て、番号が遠くの県に漏れていないことを確かめる。

## 地域を追加する

地域は二つのデータファイルで定義する。コードには触らない。

1. `scripts/regions.py` に地域名、日本語ラベル、bbox を足す
   - bbox は南、西、北、東の順である
   - 47 都道府県ぶんは `scripts/prefecture_boxes.py` が pbf の行政界から測って出す
   - 矩形は県境に沿わないので、隣県が食み込むことは避けられない
2. `scripts/expectations.py` にその地域の既知の事実を足す
   - 確実に通る路線、確実に通らない路線、点線国道を持つ路線
   - 確信のない事実は書かない。誤った期待値は失敗を無視する癖を作る
3. パイプラインを走らせる

地域の一覧は `web/data/regions.json` に自動で書き出される。地図は全国のタイルを 1 枚として読むので、画面側に作業はない。

## 配信の形

全国の一般国道は約 13 万アークある。1 つの GeoJSON では配れないので、閲覧側は特徴量を手元に持たない。

| ファイル | 中身 |
| --- | --- |
| `web/data/national-routes.pmtiles` | 全国のベクタタイル。Range 要求で読む |
| `web/data/national.meta.json` | 画面が出す集計。指定の組み合わせ単位 |
| `web/data/regions.json` | 地域の一覧。`?region=` の初期表示に使う |

この三つは git に入れない。公開するときは `scripts/publish_data.py` が data.nanase.cc(Cloudflare R2)へ直接上げる。GitHub Pages の裏側(Fastly)が Range 要求の先頭以外を壊す不具合を抱えており、Pages 経由では配れなかった。手順は README の「公開する」にある。

集計は**指定の組み合わせ**ごとに 1 行である。路線別の表では足りない。重用区間のアークは複数の路線に属するので、路線の行を足すと共有部分を二重に数える。それは地図が隠すのをやめさせたい数そのものである。

## 原則

- 判定ルールは実データの計測に基づいて決めてある
  - 思いつきで変えない
  - 変えるなら計測をやり直す
- 品質を数値で語るときは必ず計測する
  - 推測した数値を成果として書かない
