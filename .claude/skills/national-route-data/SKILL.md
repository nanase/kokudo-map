# national-route-data — 国道データの生成と品質管理

OpenStreetMap から日本の一般国道を取り出し、重用区間の全指定を保ったまま `web/data/` の配信データに変換します。あわせて、地理院地図との相違を機械的に検出します。

対象は全国 47 都道府県です。

## 生成する

```sh
uv run pipeline/extract_pbf.py     # pbf から 47 地域ぶんを切り出す
uv run pipeline/build_all.py       # 判定・検証・結合・タイル化まで通す
```

初回は pbf が必要です。約 2.5 GB です。

```sh
mise run fetch-pbf
```

段階は次のとおりです。

| 段階 | すること | 単位 |
| --- | --- | --- |
| 取得 | Geofabrik の pbf を落とす | 全国 |
| 切り出し | 地域ごとの生 OSM をキャッシュし、way に所属都道府県を付ける | 全国を 1 度読む |
| 判定 | 国道かどうかと何号かを決める | 地域 |
| 検証 | 生成物の整合性と既知の事実を確認する | 地域 |
| 式検証 | 地図スタイルと絞り込み式を確認する | 地域 |
| 政令の起終点 | 政令の別表から取り込む | 全国 |
| 結合 | 地域を繋ぎ、集計してタイルを切る | 全国 |
| 全国検証 | 結合後にしか答えられないことを確認する | 全国 |

所属都道府県は矩形では決まらないので、国土数値情報 N03 の行政区域の面で決めます(理由と実測は `pipeline/prefectures.py`)。地域の分け方は矩形のままです。面にすると裏取りの保証集合が変わり、国道の判定そのものが変わります。

1 地域だけ Overpass から作り直すなら `uv run pipeline/pipeline.py <地域>` を使います。全国を Overpass から取ってはいけません。47 都道府県は約 140 クエリ、raw 1 GB になり、公開ミラーの用途から外れます。

ブラウザでの実描画確認は `pipeline/render_check.mjs` が担います。先に `pipeline/serve.py` でローカルサーバを起動します。PMTiles は Range 要求で読むので、`python -m http.server` では配れません。

画面写真は一時ディレクトリに書き出し、最後にその場所を表示します。作業ツリーには残しません。手元に置きたいときだけ、保存先のディレクトリを引数で渡します。

## 都道府県道を生成する

都道府県道は別の工程です。pbf を 1 度読んで候補を県ごとに落とし、そこから判定します。

```sh
mise run survey-pref     # pbf から build/survey/ を作る
mise run build-pref      # 判定して build/prefectural/ を作る
```

`build/survey/` は国道にとっての `build/cache/` に当たります。作り直すのは pbf を取り直したときだけです。`mise run build-pref` はそれを読むので、pbf を読み直しません。

判定のルールは [PREFECTURAL.md](PREFECTURAL.md) にあります。国道の判定は変わりません。同じ way が国道のアークにも都道府県道のアークにもなります。

配信データは `mise run pack` が国道とは別のアーカイブに切り、画面は同じ地図に重ねます(#100・#101)。

## 判定は地域ごとに閉じている

取得は全国ですが、裏取りは地域の中で閉じたままにします。way 自身が主張する番号は、同じ地域の国道リレーションが保証する番号だけ採用します。保証集合は 1 県で数十ですが、全国をひとまとめに判定すると 459 に近づいて何も濾さなくなり、長野県道 372 号がそのまま国道 372 号として復活します。理由は [RULES.md](RULES.md) の裏取り、実例は [CASES.md](CASES.md) の 1 番・2 番・6 番です。

`verify.py` は各地域の保証集合が 459 の三分の一未満であることを、`verify_national.py` は番号が遠くの県に漏れていないことを確かめます。

## 地域を追加する

地域は二つのデータファイルで定義します。コードには触りません。

1. `pipeline/regions.py` に地域名、日本語ラベル、bbox を足す
   - bbox は南、西、北、東の順
   - 47 都道府県ぶんは `pipeline/prefecture_boxes.py` が pbf の行政界から測って出す
   - 矩形は県境に沿わないので、隣県が食み込むことは避けられない
2. `pipeline/expectations.py` にその地域の既知の事実を足す
   - 確実に通る路線、確実に通らない路線、点線国道を持つ路線
   - 確信のない事実は書かない。誤った期待値は失敗を無視する癖を作る
3. パイプラインを走らせる

地域の一覧は `web/data/regions.json` に自動で書き出されます。地図は全国のタイルを 1 枚として読むので、画面側に作業はありません。

## 配信の形

全国の一般国道は約 13 万アークあります。1 つの GeoJSON では配れないので、閲覧側は特徴量を手元に持ちません。

| ファイル | 中身 |
| --- | --- |
| `web/data/national-routes.pmtiles` | 国道のベクタタイル。Range 要求で読む |
| `web/data/prefectural-routes.pmtiles` | 都道府県道のベクタタイル |
| `web/data/national.meta.json` | 国道について画面が出す集計。指定の組み合わせ単位 |
| `web/data/pref/{region}.meta.json` | 県ごとの集計。県を選んだときに取る |
| `web/data/pref/index.json` | 全国の県と番号だけの索引。「道路を選択」が読む |
| `web/data/regions.json` | 地域の一覧。`?region=` の初期表示に使う |

`national.meta.json` には、政令の別表から取り込んだ起点・終点も入ります。地図が描く端点とは別の欄です。座標の当て方と、当たらなかったときの扱いは [data-model.md](../../../docs/data-model.md) にあります。

どれも git に入れません。公開するときは `pipeline/publish_data.py` が data.nanase.cc(Cloudflare R2)へ直接上げます。GitHub Pages の裏側(Fastly)が Range 要求の先頭以外を壊す不具合を抱えており、Pages 経由では配れませんでした。手順は [docs/architecture.md](../../../docs/architecture.md) にあります。

集計は指定の組み合わせごとに 1 行です。路線別の表では足りません。重用区間のアークは複数の路線に属するので、路線の行を足すと共有部分を二重に数えます。それは地図が隠すのをやめさせたい数そのものです。

## 原則

- 判定ルールは実データの計測に基づいて決めてある
  - 思いつきで変えない
  - 変えるなら計測をやり直す
- 品質を数値で示すときは必ず計測する
  - 推測した数値を成果として書かない
