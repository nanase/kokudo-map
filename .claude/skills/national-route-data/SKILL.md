# national-route-data — 国道データの生成と品質管理

OpenStreetMap から日本の一般国道を取り出し、重用区間の全指定を保ったまま `web/data/` の配信データに変換する。あわせて、地理院地図との相違を機械的に検出する。

## 生成する

```sh
uv run scripts/pipeline.py niigata
```

取得から検証まで通す。段階は次のとおりである。

| 段階 | すること |
| --- | --- |
| 取得 | 最も新しい Overpass ミラーを選んで取得し、キャッシュする |
| 判定 | 国道かどうかと何号かを決め、`web/data/` を書く |
| 検証 | 生成物の整合性と既知の事実を確認する |
| 式検証 | 地図スタイルと絞り込み式が MapLibre 仕様に適合するか確認する |

キャッシュから作り直すだけなら `--skip-fetch` を付ける。段階を個別に走らせるときは `scripts/` の各スクリプトを直接呼ぶ。

ブラウザでの実描画確認は `scripts/render_check.mjs` が担う。ローカルサーバを先に起動しておく必要がある。

## 地域を追加する

地域は二つのデータファイルで定義する。コードには触らない。

1. `scripts/regions.py` に地域名、日本語ラベル、bbox を足す
   - bbox は南、西、北、東の順である
   - 矩形は県境に沿わないので、隣県が食み込むことは避けられない
2. `scripts/expectations.py` にその地域の既知の事実を足す
   - 確実に通る路線、確実に通らない路線、点線国道を持つ路線
   - 確信のない事実は書かない。誤った期待値は失敗を無視する癖を作る
3. パイプラインを走らせる

地域の一覧は `web/data/regions.json` に自動で書き出され、画面の切替に使われる。

## 原則

- 判定ルールは実データの計測に基づいて決めてある
  - 思いつきで変えない
  - 変えるなら計測をやり直す
- 品質を数値で語るときは必ず計測する
  - 推測した数値を成果として書かない
