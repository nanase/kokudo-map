# 公開データを更新する

配信データを作り直し、R2 に上げるまでの手順です。

更新の間隔は決めていません。無償で公開している地図に鮮度の約束は要らないので、思い立ったときに人が回します。画面と README は不定期であることを述べています。

段は 1 つの命令に畳みません。畳むと段の境目が消え、落ちたときに「どの段で何が期待と違ったか」が失われます。所要も性質も違う段を 1 本に隠す利益はありません。

## 段

| 段 | 命令 | 所要 |
| --- | --- | --- |
| 取得 | `mise run fetch-pbf` | 10〜20 分 |
| 切り出し | `mise run extract` | 数分 |
| 生成 | `mise run build-all` | 4.8 時間 |
| 突き合わせ | 次節 | 数分 |
| 公開 | `mise run publish-data` | 数分 |

取得の前に `build/pbf/japan-latest.osm.pbf` を消してください。`fetch-pbf` は `curl -C -` で続きから取ります。Geofabrik は毎日別の中身に差し替えるので、前回の pbf が残っていると、続きは前回の続きになりません。

生成は pbf の基準時刻から 7 日以内に終えてください。数え始めるのは取得した時ではありません。Geofabrik が切り出した時刻を pbf 自身が持っており、`extract` がそれを `osm_timestamp` として引き継ぎます。落とした時点で既に 1 日ほど古いので、手元で使えるのは実質 6 日です。

8 日以上になると、地域ごとの検証が 47 県すべてで落ちます。最初の県で分かるので 4.8 時間は待ちませんが、`rebuild` も同じ門を通るため県を直す道はありません。pbf の取り直しからやり直します。この門は更新頻度の数字ではなく、「古い pbf から作ってしまった」を止める門です。

`build-all` は 47 都道府県の判定と検証から、台帳・結合・タイル化・全国検証までを通します。1 県でも落ちれば配信データは作られません。落ちた県だけを直したら、`mise run rebuild <地域>` で作り直し、`mise run pack` で結合から再開できます。

## 公開する前に突き合わせる

公開中の meta と、いま作った meta を比べます。

```sh
curl -fsS https://data.nanase.cc/national.meta.json -o build/published.meta.json
```

`-f` が要ります。付けないと、R2 が落ちているときにエラーページが `build/published.meta.json` になり、比べる相手を黙って失います。

次のどれかに触れたら、公開せずに理由を確かめます。

| 見る数 | meta のどこか | 止める幅 |
| --- | --- | --- |
| 総延長 | `total_km` | ±0.5 % |
| 単一路線の延長 | その路線を含む `combinations` の `km` の和 | ±30 km |
| 指定の組み合わせ | `combinations` の要素数 | ±2 % |
| 路線数 | `combinations` の `refs` を集めた集合の大きさ | 459 でない |

前回の記録は要りません。公開中の meta がその記録そのものです。

幅を超えたこと自体は誤りの証拠ではありません。1 週間ぶんの差を実測したときは、5 km 以上動いた路線は 459 のうち 1 本(国道 206 号、−25.00 km)だけで、それも道路ではなく OSM 側のリレーションの編集でした。確かめるのは「どの路線がなぜ動いたか」であって、「動いたかどうか」ではありません。

## 間が空いたときだけ壊れる場所

次は「外部が変わった」であって「手順が間違っている」ではありません。この区別を先に置いておけば、落ちるたびにゼロから切り分けずに済みます。

| 場所 | 空くと起きること |
| --- | --- |
| `build/decree` | 90 日でキャッシュが切れ、e-Gov 法令検索への取得が走る |
| 国土数値情報の年度 | N13 は `N13-24`、N03 は `N03-2026` を指している。年度が変われば URL ごと変わる |
| Geofabrik | `japan-latest.osm.pbf` のパスとミラーが変わりうる |
| wrangler のログイン | 期限切れは `publish-data` の入口で判明する。4.8 時間の生成が終わった後になる |
| mise が入れる道具 | node 26・python 3.14・bun 1.3・uv 0.12。版が動けば `mise install` からやり直す |

## 更新しない選択

自動化も監視も置いていません。誰も見ていないのに動き続ける仕組みは、OSM の誤りを検査なしで配ります。止まって古くなるほうが、動き続けて静かに誤るより正直です。

更新頻度を上げても正しさは買えません。出どころが OSM である以上、修正も誤りも同じ速さで届きます。
