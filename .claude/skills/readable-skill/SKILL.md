# readable-skill — スキルを書くときの執筆規律

スキルの文書の構造を整える規律である。単体で読めるか・短いか・スキル外に依存しないかを見る。文章の読みやすさとコードの規約適合は別軸で、別のスキルが担う。

## 規律

1. アトミックスキルを他のスキルに依存させない
   - 「次は ○○ を呼ぶ」と名指ししない
   - 呼ぶ順・対応付けは束ねる統合スキルに置く
   - 隣接スキルは名前でなく役割で書く
2. 挙動をスキル外のドキュメントに書かない
   - その文書だけ読めば従える状態
   - 明文規約（CLAUDE.md・ADR）の出典を指す参照は許す
3. 同じことを 2 か所に書かない
   - 1 つの事実は 1 か所に置く
   - 他のスキル・CLAUDE.md と同じ説明を繰り返さない
4. 重い節を本体に抱え込まない
   - 厚い説明は子文書へ出し、本体は呼ぶだけ
5. 決定的なコマンド列を文書に書かない
   - 固定手順はスクリプトへ出し、文書からは呼ぶだけ

## description は一言にする

description はスキルを呼ぶ判断にだけ使う。「何をするか」と「いつ使うか」を一言で書く。本文の手順・規則・理由を詰め込まない。
